# Merkle Tree Cross-Language Compatibility

## The Problem

The original JS implementation of the Merkle Tree hashed hex string representations of children:

    sha256(hex_string_left + hex_string_right)   <-- WRONG

But the Rust contract hashes raw bytes:

    sha256(raw_bytes_left || raw_bytes_right)    <-- CORRECT

This meant a Merkle Root generated by the backend could NOT be verified by the on-chain contract. The two implementations produced different hashes for the same data.

## The Fix

The JS backend now converts hex strings to raw bytes before hashing:

    sha256Pair(leftHex, rightHex) {
        const left = hexToBytes(leftHex);   // raw 32 bytes
        const right = hexToBytes(rightHex); // raw 32 bytes
        return sha256(Buffer.concat([left, right]));
    }

    Same vectors are embedded.
    test_js_rust_cross_compatibility asserts the JS-generated proof verifies in Rust.

If either side ever changes the hashing logic, this test will fail on CI.

## Rules for Future Changes

1. Never hash hex strings. Always hash raw bytes.
2. Sort lexicographically (if left <= right, hash(left, right)). Both sides must match.
3. If you change the leaf format (tx.id:from:to:amount:type:time), update both JS and Rust.
4. Run `cargo test` and `node test_merkle.cjs` after any change.
